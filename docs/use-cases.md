# Use Cases

This document defines the first major product directions for OpenToolHub.

## Why use cases matter

Public tools are most useful when they are organized around real needs.

A user does not usually start with a list of APIs. They start with a problem:

- I want to help people plan travel
- I need a local city dashboard
- I want to build a public health tracker
- I want an AI research helper
- I want a startup MVP using public data

OpenToolHub exists to turn those problems into practical stacks and starter paths.

## Use case 1: Travel and local discovery

### Problem
People want quick, relevant local information while traveling or exploring a city.

### Typical goals
- check the weather for a trip
- find routes or local points of interest
- compare destination costs
- keep local activity updates in one place
- build a personalized travel planner

### Typical tool categories
- weather
- maps and geolocation
- currency conversion
- travel and calendar data
- local directories and attractions

### Example stack
- weather data API
- map and geocoding service
- local POI or city directory
- exchange rate API
- holiday or event data source

### Why it matters
This is one of the clearest real-world use cases for public tools. It connects everyday needs with practical digital products.

## Use case 2: City and local information dashboards

### Problem
People need better local information dashboards that combine city data, maps, updates, and public resources.

### Typical goals
- show local service information
- display weather and conditions
- highlight public events or updates
- present city events and neighborhood context
- help people discover local options faster

### Typical tool categories
- mapping and geolocation
- local event data
- weather and environment data
- civic or public datasets
- news, updates, and alerts

### Example stack
- map service
- weather feed
- event or local directory API
- public data source
- alert or news feed

### Why it matters
This type of product helps people navigate city life more easily and gives communities a simple digital layer for practical information.

### Typical tool categories

- maps and geolocation

## Use case 4: AI research and information workflows

### Problem
People need tools that help gather, organize, summarize, and act on information from multiple open sources.

### Typical goals
- research a topic quickly
- collect information from multiple public sources
- summarize public updates
- create AI-powered assistants with real-world tools
- make data easier to understand and act on

### Typical tool categories
- search and retrieval tools
- news data
- public knowledge sources
- translation or summarization services
- document and knowledge APIs

### Example stack
- news source
- open knowledge source
- translation or language tool
- summarization service

### Why it matters
This is one of the clearest pathways toward AI-powered public utility tools.

### Problem
Startups and builders need to prototype quickly without building every feature from scratch.

### Typical goals

- launch a simple product with public data sources
- build a lean digital service with minimal infrastructure

### Typical tool categories
- maps and location
- finance or simple market data
- search
- news or discovery APIs
- public data and local information sources

### Example stack
- map service
- public dataset
- search or content API

- local discovery or business data

### Why it matters
This use case is the practical bridge between open public tools and fast product experimentation.

## Use case 6: Public-interest and civic tools

### Problem
Civic teams, nonprofits, and community builders need to turn scattered public
information into something residents can actually use.

### Typical goals
- help people find local services and public information
- combine open datasets with maps and local context
- surface relevant public updates without building a newsroom
- give a community a maintainable information portal

### Typical tool categories
- public datasets
- maps and geolocation
- local discovery and points of interest
- news and public information feeds

### Example stack
- an open data source such as Data.gov or the World Bank
- a map and location layer
- a local services or places source
- a public information or news feed

### Why it matters
This use case keeps the project grounded in public value rather than novelty: the
result should help someone answer a real question about their own community.

## Use case 7: Climate resilience and adaptation

### Problem
Communities need to understand local climate hazards and decide where adaptation work matters most, but the evidence is split across weather services, open data portals, and health agencies.

### Typical goals
- compare historical climate conditions with current alerts
- identify neighborhoods exposed to heat, flooding, or other hazards
- connect climate risk to population and health context
- produce a traceable briefing for local planning decisions

### Typical tool categories
- weather and environment data
- public datasets
- maps and geolocation
- health and public-interest data

### Example stack
- NASA POWER for historical climate and meteorological context
- National Weather Service for forecasts and alerts
- World Bank or Data.gov for public indicators
- OpenStreetMap for local context
- WHO or CDC data for health impact

### Why it matters
Climate data becomes useful when it is tied to a place and the people who live there. The result should support decisions without hiding uncertainty or inventing predictions.

## Use case 8: Community food access

### Problem
Residents and community organizations need a clear view of where affordable, nutritious food is available and where access gaps overlap with income and distance.

### Typical goals
- map groceries, markets, pantries, and meal programs
- add nutrition and product context
- compare food access across neighborhoods
- help organizers target outreach and investment

### Typical tool categories
- food access and nutrition
- public datasets
- maps and geolocation
- local discovery

### Example stack
- USDA FoodData Central for nutrition data
- Open Food Facts for product and label data
- US Census ACS for neighborhood context
- OpenStreetMap for distance and map context
- Overpass or Foursquare for local food resources

### Why it matters
Food access depends on distance, cost, and available options, not just the number of stores. Connecting nutrition data to local places helps communities see the gap and act on it.

## Use case 9: Open research data

### Problem
Research outputs are spread across repositories and indexes, and ordinary search results often lose the DOI, license, and citation trail that make them reusable.

### Typical goals
- search datasets, preprints, and publications in one flow
- preserve source metadata for every result
- follow citations and related records
- summarize retrieved evidence with links back to the source

### Typical tool categories
- research data and scholarly records
- search and retrieval
- AI workflows and retrieval

### Example stack
- Zenodo for datasets, software, and DOI records
- arXiv for preprint metadata
- OpenAlex and Crossref for scholarly metadata
- OpenAI or Hugging Face Inference for summaries after retrieval

### Why it matters
Open research is only reusable when its provenance survives the search experience. Citations and licenses should be product features, not footnotes.

## Use case 10: Housing affordability

### Problem
Rent numbers alone do not show whether housing is affordable. Residents, advocates, and planners need to compare rents with local incomes and neighborhood conditions.

### Typical goals
- compare rent benchmarks with household incomes
- identify neighborhoods under the most pressure
- add transit, services, and population context
- produce an auditable briefing for housing decisions

### Typical tool categories
- housing and affordability data
- public datasets
- maps and geolocation
- local discovery

### Example stack
- HUD Fair Market Rents and income limits for rent benchmarks
- US Census ACS for income and tenure data
- Data.gov or World Bank for additional public context
- OpenStreetMap for neighborhood context
- Overpass for nearby services and transit

### Why it matters
Affordability is a relationship between cost and income. Making that relationship visible helps communities ask better questions and prioritize action.

## Use case 11: Transit access

### Problem
A transit map shows where vehicles go, but not whether people can reach jobs, groceries, schools, or health care.

### Typical goals
- show routes, stops, and service alerts
- connect transit service to daily destinations
- compare access across neighborhoods and times of day
- add population and equity context

### Typical tool categories
- transit and mobility
- maps and geolocation
- local discovery
- public datasets

### Example stack
- MBTA V3 API for Boston-area service and alerts
- Transitland for aggregated feeds in other regions
- OpenStreetMap for streets and map context
- Overpass for destinations and daily needs
- US Census ACS or Data.gov for population context

### Why it matters
Transit is infrastructure for reaching opportunity. Showing service next to destinations and population context turns a route map into a practical equity tool.

## How OpenToolHub uses these use cases

Each use case in `data/use-cases.json` is connected to:

- relevant categories
- a stack with alternative APIs per slot
- starter templates
- a worked example
- the site and CLI that resolve a query to all of the above

To see the current list, run `python3 scripts/recommend.py --list` or browse the
[use case index](../site/use-cases.html). The data model is documented in
[data-model.md](data-model.md).
