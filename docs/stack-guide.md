# Stack guide

This guide explains how OpenToolHub organizes real-world tool combinations.

## Why stack-based thinking matters

A single API is rarely enough.
Most useful products are built from multiple tools that work together.

Examples:

- travel planner = weather + maps + finance + calendar
- city dashboard = maps + weather + local data + news
- AI research tool = search + docs + translation + summarization
- public health dashboard = health data + maps + alerts + reporting

## How OpenToolHub approaches stacks

Each stack should answer:

- what problem is being solved?
- which categories are relevant?
- which APIs fit the job?
- what is the expected user experience?
- which tools are most useful for builders and AI systems?

## Recommended stack structure

A stack entry should include:

- a name
- a use case ID
- API list
- a description
- why it is useful
- which user segment it serves

## Example stack patterns

### Travel stack

- weather data
- maps and geolocation
- local attractions or destinations
- currency conversion
- travel or holiday data

### Research stack

- public information APIs
- news and media sources
- translation tools
- summarization or AI services

### Civic stack

- public data sources
- local maps
- health or environment data
- alert feeds
- dashboards and reporting tools

## Contribution goal

We want contributors to add valuable stack examples for real project ideas.
This is how we grow beyond a static list into a practical builder ecosystem.
